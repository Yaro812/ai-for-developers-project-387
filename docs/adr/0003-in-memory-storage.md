# Данные хранятся в памяти процесса

Типы встреч и бронирования хранятся в памяти единственного процесса Fastify, а Postgres приложение не использует. Задание не требует сохранять данные после перезапуска, а однопоточный Node защищает от одновременных пересекающихся бронирований без базы: обработчик проверяет пересечение и сохраняет бронирование синхронно, без `await` между этими действиями. Без базы тестам и CI не нужен Postgres, а для запуска в облаке достаточно одного контейнера. Вариант с Postgres отвергнут: он добавляет драйвер, миграции, базу в тестах и CI и управляемую базу в облаке ради свойства, которое приёмка не проверяет.

## Последствия

- Работает только один экземпляр приложения, и перезапуск или засыпание контейнера сбрасывает все типы встреч и бронирования. README предупреждает об этом.
- `buildApp` создаёт своё пустое хранилище, поэтому у каждого теста чистые данные.
- Если понадобятся сохранение или несколько экземпляров, хранилище переводится на Postgres, а пересечения запрещает ограничение исключения по интервалу бронирования.
